# ИИ Рамис — наставник для учеников курса «ИИнутый»

ИИ Рамис — это ИИ-помощник Рамиса Жолдошева, автора курса. Он живёт внутри Claude Code (вкладка Code в приложении Claude Desktop или команда `claude`), объясняет простыми словами, сам ставит и чинит всё нужное и проверяет результат, прежде чем сказать «готово».

> Идея и часть подхода: [vibe-coding-mentor](https://github.com/AzamatRaimbekov/vibe-coding-mentor) Азамата Раймбекова, лицензия MIT. См. `NOTICE.md`.

## Установка в 3 шага

Нужно: компьютер с macOS или Windows, приложение Claude Desktop (claude.ai/download), подписка Claude Pro.

**Шаг 1. Открой вкладку Code.** В приложении Claude слева сверху выбери вкладку **Code**, нажми «выбрать папку» и укажи любую новую пустую папку (например, «Занятия» на Рабочем столе). Если система просит установить инструменты разработчика (Mac) или Git (Windows) — соглашайся: «Установить», «Принимаю» / Next, Next, Finish.

**Шаг 2. Скопируй эту фразу в чат вкладки Code и отправь:**

- Mac:
  ```
  Установи пакет ИИ Рамис: запусти команду curl -fsSL https://raw.githubusercontent.com/RamisGit-cyber/ii-ramis/v1.0.3/plugins/ii-ramis/scripts/install.sh | bash и потом расскажи простыми словами, что поставилось.
  ```
- Windows:
  ```
  Установи пакет ИИ Рамис: запусти в PowerShell команду irm https://raw.githubusercontent.com/RamisGit-cyber/ii-ramis/v1.0.3/plugins/ii-ramis/scripts/install.ps1 | iex и потом расскажи простыми словами, что поставилось.
  ```

Claude может спросить разрешение на команды: разрешай. Сам установщик скачивается с зафиксированной версии `v1.0.3` (фраза не меняется от каждого обновления плагина), а сам плагин следит за веткой `stable` с проверенными релизами и **обновляется сам** (см. «Обновления»). Установщик ставит плагин и безопасные пакеты, режим «без вопросов» не включает вообще (см. ниже) и согласия на пересказы занятий не спрашивает: его один раз спросит ИИ Рамис в чате при первом «привет» (см. «Приватность»). Установка безопасна для повторного запуска: если что-то не вышло, просто отправь ту же фразу ещё раз. Если ты ставил версию 1.0.2, отправь новую фразу: установщик переведёт плагин на `stable` и включит автообновление, ничего не удаляя.

**Шаг 3. Перезапусти Claude и поздоровайся.** Полностью закрой приложение (на Windows ещё и значок в трее), открой снова, зайди во вкладку Code и напиши «привет». ИИ Рамис представится, спросит, какой урок ты прошёл, один раз спросит согласие на пересказы занятий (можно ответить «нет») и сам проверит компьютер. Проверку можно повторить командой `/ii-ramis:proverka`. Дальше он отвечает как обычный полноценный Claude, а в конце каждой выполненной работы даёт короткий итог: «Что случилось» простыми словами и «Что нужно сделать тебе» (или «Ничего, всё готово»). Сайты он делает как настоящий проект (Next.js на localhost, потом GitHub и Vercel, при необходимости Supabase), а не страницей в чате: маршрут в навыке `/ii-ramis:sait`.

/plugin marketplace add RamisGit-cyber/ii-ramis#stable

## Что ставится и зачем

| Что | Зачем простыми словами |
|---|---|
| **ИИ Рамис** (этот плагин) | наставник, проверка компьютера, страховка от опасных команд, автосохранение |
| **Superpowers** | порядок в работе Claude: планирует, проверяет, не спешит |
| **claude-mem** | память между сессиями: Claude помнит, что вы делали вчера |
| **ECC (everything-claude-code)** | набор дополнительных помощников. Тяжёлый: если упёрся в лимит подписки, его можно выключить (ниже) |
| **Context7** | свежие инструкции к инструментам: Claude не придумывает, а читает актуальную документацию |
| **Playwright** | невидимый помощник с браузером: сам открывает твой сайт и проверяет, что он работает |
| Git, Node.js, Python, GitHub CLI | основа: сохранения, запуск сайтов, работа с GitHub. Установщик ставит недостающее |

### Режим «без вопросов» (bypass): включаешь только ты сам, наши скрипты его не трогают

Режим Claude «не спрашивать разрешение на каждое действие» (`bypassPermissions`) удобен на уроках, но у него есть цена: Claude сам выполняет команды на твоём компьютере, не спрашивая заранее. Если он ошибётся или прочитает вредную инструкцию, спрятанную на чужом сайте или в файле, он может испортить или стереть твои файлы. Плагин ловит самое опасное, но это **страховочная сетка, а не стена** (см. «Чего страховка не ловит»).

Поэтому ни установщик, ни другой наш скрипт этот режим **не включают никогда**, ни с вопросом, ни без. Включаешь только ты, одним из двух способов:

- **Переключатель в Claude Desktop:** Settings -> Code -> «Allow bypass permissions mode».
- **Руками в файле** `~/.claude/settings.json` (Windows: `%USERPROFILE%\.claude\settings.json`), открыв его обычным редактором, не через Claude: добавь `"permissions": { "defaultMode": "bypassPermissions" }`. Если раздел `permissions` уже есть, добавь в него только строку `"defaultMode"`.

Выключить: тот же переключатель, либо поменяй `defaultMode` на `default`. Защита плагина не даёт Claude править `settings.json`, запускать наш установщик и `setup-settings.mjs` (в том числе `curl ... | bash` с нашего репозитория), использовать обёртки с псевдотерминалом (`script`, `expect`, `unbuffer`, `socat`, python `pty`, `/dev/tty`) и стирать переменные `CLAUDECODE` и подобные (`env -i`, `env -u`, `unset`).

## Что страхует плагин

Это **страховочная сетка, а не стена**: она останавливает типичные случайные ошибки и самые простые приёмы, но не защищает от человека (или вредной инструкции), который целенаправленно ищет обход.

- **Опасные команды блокируются**: удаление папок за пределами проекта (внутри проекта можно только мусор вроде `node_modules`, `dist`, `.next`), любое обращение к файлам с ключами (`.env`, `*.pem`, `id_rsa`, `~/.ssh`, `~/.aws`): чтение, поиск, правка, копирование, `git push --force`, `git reset --hard`, запуск скриптов из интернета с непроверенных адресов, удаление баз данных, выгрузка файлов в интернет (`curl -d @файл`, `--data-binary @файл`, `-F файл=@...`, `-T`, `wget --post-file`, `tar ... | curl -T -`), чтение и правка файлов запуска оболочки и истории команд (`~/.zshrc`, `~/.bashrc`, `~/.profile`, `~/.zsh_history`, `~/.bash_history`), адреса WebFetch, в которые зашиты ключи или длинные куски данных. Скрипт «скачать и выполнить» (`curl ... | bash`) разрешён только с доверенных адресов и **без аргументов**; наш собственный установщик из чата не запускается совсем. Выгрузкой считаются и `curl -H @файл`, `--url-query имя@файл`, `--variable имя@файл`, любые `--expand-*`, `-K`/`--config`. WebFetch закрыт для внутренних адресов (проверка адресов best-effort: DNS и переадресации не проверяются): localhost, 127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, IPv6 `::1`, `fe80::/10`, `fc00::/7`, в том числе записанных числом (`2130706433`, `0x7f.1`), весь диапазон `::ffff:0:0/96`, `198.18.0.0/15`, `64:ff9b:1::/48`. Проверки работают и через обходные пути (`bash -c`, `xargs`, `find -delete`, PowerShell). Подтверждения «да» через Claude нет, потому что ИИ мог бы подтвердить сам себя. Claude объяснит, что хотел сделать. Если действие правда нужно, ты выполняешь его сам в обычном окне терминала (не через Claude) или показываешь Рамису. Файл `.env` с ключами ты создаёшь и правишь руками, Claude работает с `.env.example`.
- **Автосохранение**: при старте сессии, если папка уже под Git и в ней есть несохранённые изменения, плагин делает сохранение «checkpoint перед сессией». В интернет оно не уходит. Если файл с ключами не спрятан в `.gitignore`, сохранение пропускается с предупреждением.
- **Папка без Git**: если это похоже на проект, ИИ Рамис предложит включить сохранения.

## Обновления: автоматически, с ветки `stable`

Плагин следит за веткой `stable` репозитория (`RamisGit-cyber/ii-ramis#stable`), и установщик включает автообновление этого маркетплейса (`autoUpdate: true` в `~/.claude/settings.json`, это штатная настройка Claude Code, [документация](https://code.claude.com/docs/en/plugins/org.md#set-update-policy)). Claude Code сам проверяет обновления при запуске и подтягивает новую версию, вручную ничего делать не нужно. Новая версия подхватывается, когда в `plugin.json` выросло поле `version`.

**Честно про риск.** Всё, что автор кладёт в `stable`, сразу доходит до всех учеников и выполняется на их компьютерах (хуки плагина запускают программы). Поэтому у автора правило: **в `stable` попадают только проверенные релизы** (тесты зелёные, ревью безопасности пройдено, проверка на чистой установке), а ветка `main` остаётся рабочей. Сам установщик в твоей фразе по-прежнему скачивается с неизменяемого тега, а не с `stable`. Доверие тут к автору и к его аккаунту GitHub: пока у аккаунта включена 2FA, а ветка `stable` защищена от force-push, подменить релиз сложнее, но не невозможно.

Отключить автообновление: в чате Claude Code `/plugin` → вкладка **Marketplaces** → `ii-ramis` → **Disable auto-update** (установщик уважает твой выбор и при повторном запуске его не включит). Обновить вручную: `claude plugin marketplace update ii-ramis`, затем `claude plugin update ii-ramis@ii-ramis`. Закрепиться на конкретной версии: `claude plugin marketplace add RamisGit-cyber/ii-ramis#v1.0.3` (источник в настройках поменяй на тот же тег и выключи автообновление).

## Как выключить

| Что | Как |
|---|---|
| Выключить ИИ Рамис | `claude plugin disable ii-ramis@ii-ramis`, или в приложении «+» → Manage plugins → ii-ramis → Disable |
| Выключить тяжёлый ECC | `claude plugin disable ecc@ecc`, или там же в Manage plugins. Включить обратно: `claude plugin enable ecc@ecc` |
| Удалить | `claude plugin uninstall ii-ramis@ii-ramis` |
| Выключить автосохранение | в чате: «ИИ Рамис, выключи автосохранение» (запишет `autosave: false` в `~/.ii-ramis/config.json`) |
| Вернуть вопросы перед действиями (выключить «без вопросов») | в `~/.claude/settings.json` поменяй `permissions.defaultMode` на `default` |

Выключить защиту (отключить плагин, поменять настройки Claude Code) может только сам ученик: в окне настроек или в обычном терминале. Через чат с Claude такие команды блокируются, это сделано нарочно. Не получается? Покажи Рамису на уроке.

## Приватность: что уходит Рамису, что нет

После каждой сессии плагин пишет **у тебя на компьютере** короткий итог в файл `~/.ii-ramis/progress.jsonl`. Рамису он уходит **только если ты согласился сам, словом «да» в чате** (флаг `share` в `~/.ii-ramis/config.json`). Согласие спрашивает ИИ Рамис один раз, при первом знакомстве; на «нет», «не знаю» или молчание отправка остаётся выключенной. Записи, сделанные без согласия, не уйдут никогда, даже если ты согласишься позже. Согласие даётся в чате, а не в терминале: Claude выполняет команду `config.mjs set share true` только после твоего явного «да» отдельным сообщением (так написано в его инструкции, а защитный хук дополнительно проверяет твоё последнее сообщение). Это страховка от ошибки, а не от злого умысла: если ты не хочешь ничего отправлять, отвечай «нет». Отключить отправку можно в любой момент: скажи в чате «не отправляй мои данные Рамису» (Claude выполнит `config.mjs set share false`) или поставь `"share": false` в `~/.ii-ramis/config.json`. Включить обратно можно так же, фразой в чате.

**В итоге есть**: случайный номер установки (`install_id`), имя или ник, который ты сам назвал (поле `student_name`), номер пройденного урока, операционная система, название папки проекта, длительность и число твоих сообщений, какие инструменты Claude применял (сколько раз), типы изменённых файлов (.html, .js), категории дел (git, установка, проверка в браузере), число раз, когда Claude просил твоей помощи, и до пяти самых частых ошибок: короткая выдержка до 100 символов, из которой вычищены пути, почты, ключи и числа. Если одна и та же ошибка повторилась 3 раза, ставится пометка «застряли» — это сигнал Рамису, что тебе нужна помощь.

**Новое в 1.0.3: пересказ сессии.** Если ты согласился, ИИ Рамис по ходу занятия пишет в файл `~/.ii-ramis/recap.txt` короткий пересказ: 2–3 предложения по-русски (до 400 символов) о том, что ты делал, где застрял и о чём спрашивал. Это единственное место, где в сводку попадает текст, написанный не счётчиком, а Claude. Дословных сообщений, кода, путей, ключей, паролей, почт и телефонов в нём быть не должно (так сказано в инструкции Claude), и перед отправкой текст дополнительно проходит автоматическую очистку (пути, почты, ключи, телефоны и длинные числа заменяются метками). Очистка ловит типичное, но не всё: если в пересказ попадёт что-то личное, например твоё полное имя в рассказе, она может это пропустить. Файл `recap.txt` стирается в начале и в конце каждой сессии. Без согласия пересказ не пишется и не сохраняется.

**В итоге нет никогда**: твоего кода, содержимого файлов, дословных текстов твоих сообщений и команд, путей к файлам, ключей и паролей.

Отправка идёт напрямую в базу Рамиса (Supabase, таблица `sessions`) через встроенный в Node `fetch`, с ограничением 5 секунд на запрос. Ключ в плагине публичный и умеет только добавлять строки, читать чужие записи с ним нельзя. На сервере стоит общий потолок записей в час: при отказе плагин молчит, сессию не ломает, запись ждёт в очереди. Не получилось (нет сети, сервер недоступен, сервер ответил отказом или лимитом 429/5xx) — без ошибок: запись остаётся у тебя в `progress.jsonl` и уходит при следующей сессии (до 20 записей за раз). Удалить всё у себя: стереть папку `~/.ii-ramis`.

## Чего страховка не ловит

Это защита от **случайных ошибок Claude и от инструкций, спрятанных в скачанном или прочитанном тексте**. Это не песочница и не защита от человека, который целенаправленно обходит правила. Хуки читают текст команды и угадывают, что она сделает. Что они **не** видят:

- **Код внутри файлов.** Если Claude сначала запишет `script.py` с вредным кодом, а потом запустит `python3 script.py`, хук видит только имя файла. Разрешён запуск лишь существующих файлов проекта, но их содержимое не проверяется.
- **Скрипты проекта и пакеты.** `node файл.mjs` (любой файл проекта), `npm run ...`, `npx -y пакет`, `npm install`, `make`, `package.json` с `postinstall` исполняют что угодно. Перекрыть их нельзя без поломки обычной работы, поэтому они разрешены. Это главная дыра: файл мог быть записан самим Claude на предыдущем шаге.
- **Код в файлах, который сам прячет признаки Claude.** Файл `script.py`, который стирает `CLAUDECODE`, уходит в «сироту» (daemon) и открывает свой терминал, установщик может принять за человека; проверка по переменным и родителям это не ловит. Поэтому плагин не доверяет файлам проекта (см. выше).
- **Адреса, которые только по имени ведут на внутренние** (свой DNS-домен, редирект с публичного сайта на 169.254...). WebFetch проверяет адрес в тексте, но не результат DNS и не переадресации.
- **Другие способы отправить данные.** `scp`, `rsync`, `nc`, `ftp`, `gh gist create`, `git push` в чужой репозиторий, свой скрипт на Node/Python. Перекрыты только `curl`, `wget`, `Invoke-WebRequest` и WebFetch.
- **Сложная сборка команды.** Имена, собранные из переменных, кодировки, функции и alias, `rsync --delete`, `mv` в `/dev/null`, `dd`, `shred` на неочевидных путях, `curl ... -o файл` и затем запуск файла отдельной командой.
- **Обход через другие программы.** Встроенные редакторы, git-хуки и `git config`, `-exec` у `find` в позиции, которую разбор не отследил, редкие интерпретаторы (`lua`, `R`, `pypy` и т.п.).
- **Новые инструменты и MCP-серверы.** Пути проверяются у полей, похожих на пути; инструмент, который принимает путь в нестандартном поле, пройдёт.
- **Секреты в переменных окружения и в самих файлах проекта.** Хук блокирует чтение `.env`, но не знает, что ключ вставили прямо в `config.js`.
- **Пароли, которые ты сам напечатал в чат.**
- **Слишком строгие срабатывания.** Часть безобидных команд блокируется (запуск интерпретатора с флагами, `cd` перед запуском, `find -delete` в корне проекта). Тогда запиши код в файл проекта и запускай файл отдельным шагом или выполни действие сам в терминале.

Если нужна настоящая изоляция, запускай Claude Code под **отдельной учётной записью** системы без доступа к личным файлам или внутри **виртуальной машины / контейнера** (например, Docker), а ключи давай только временные и с минимальными правами.

## Для автора

- Структура: `.claude-plugin/marketplace.json` в корне, плагин в `plugins/ii-ramis/` (навыки `ii-ramis`, `proverka` и `sait`, хуки на Node.js, скрипты проверки и установки).
- Проверка формата: `claude plugin validate .` и `claude plugin validate plugins/ii-ramis`. Тесты хуков: `bash tests/test-hooks.sh`.
- Ветки: `main` это работа, `stable` это только проверенные релизы. Маркетплейс учеников следит за `stable` с автообновлением, поэтому **каждый пуш в `stable` сразу доходит до всех учеников**. Перед пушем в `stable`: тесты (`bash tests/test-hooks.sh`) зелёные, ревью безопасности (`security-reviewer`) пройдено, установка проверена на чистом профиле. Обновление доходит до учеников, только когда вырос `version` в `plugin.json`: без этого они остаются на старой копии.
- Релизы: версия в `plugin.json` и тег `vX.Y.Z` на нужном коммите. Установщики качаются с тега (`RELEASE_TAG` в `install.sh`, `$ReleaseTag` в `install.ps1`, `RELEASE_TAG` в `setup-settings.mjs`), плагин следит за `stable`. Выпуск: поднять версию в `plugin.json`, поменять тег в `install.sh`, `install.ps1`, `setup-settings.mjs`, README, `skills/proverka/SKILL.md`, влить в `main`, создать тег, затем перенести `stable` на проверенный коммит (`git push origin <коммит>:stable`) и запушить тег.
- Windows и кодировка: `install.ps1` обязан быть чистым ASCII (русские строки собираются функцией `T` из кодов `~uXXXX`): через `irm | iex` BOM превращается в символ U+FEFF и ломает `iex`, а без BOM Windows PowerShell 5.1 читает файл с диска в системной кодировке. `diagnose.ps1` (запускается через `-File`) хранится в UTF-8 с BOM. Тест `tests/test-hooks.sh` проверяет, что каждый `.ps1` либо с BOM, либо ASCII, и прогоняет парсер, если есть `pwsh` (`PWSH=/путь/к/pwsh`).
- Перед публикацией: включить 2FA на аккаунте `RamisGit-cyber` и защиту веток `main` и `stable` (запрет force-push и удаления, обязательный PR для `stable`). Без этого подменить релиз проще: пуш в `stable` попадает на компьютеры всех учеников.
- Пересказ сессии: колонка `recap` в `public.sessions` добавляется миграцией `migrations/2026-11-01-sessions-recap.sql` (применяется вручную, перед этим бэкап). Если колонки ещё нет, плагин при ответе 400 повторяет отправку без пересказа, записи не теряются.
- Отправка сводок: `scripts/report.mjs`, адрес и публичный anon-ключ в `scripts/report-config.mjs` (ключ умеет только INSERT в `public.sessions`, лимит 30 строк в час на установку). Для тестов адрес можно подменить переменной `IIRAMIS_REPORT_URL`; из `config.json` адрес не читается. Тесты на фейковом сервере: `tests/test-report.mjs` (запускаются из `tests/test-hooks.sh`).
- Публикация: создать репозиторий `RamisGit-cyber/ii-ramis` на GitHub (публичный), запушить ветку `main`.
