## 2.5.0 (04.11.2026) — набор ставится даже в песочнице Claude Desktop

- **Что сломалось на уроке 5.** В Claude Desktop (вкладка Code) команды Claude идут в песочнице, и она не даёт им писать в системную папку `~/.claude` и в файл `~/.claude.json`. Ученики получали «Operation not permitted», набор не вставал. Это защита приложения, а не поломка, и добавить эти пути в разрешённые нельзя (документация Claude Code, раздел Sandboxing).
- **Как починено.** Набор теперь ставит скрипт `hooks/kit-install.sh`, который приложение запускает при старте сессии как хук. Хуки плагинов выполняются вне песочницы, так что запись в `~/.claude` проходит. Без вопросов, один раз: флаг «уже поставлено» — `~/.ii-ramis/nabor.json` (`status: ok`, `kit: 2.5.0`). Песочницу никто не выключает и не обходит.
- Отказ «не ставь набор» работает: установка останавливается на следующем шаге, уже поставленное не удаляется. Отключить можно и заранее: переменная `II_RAMIS_NO_KIT=1`.
- В набор добавлены **HyperFrames** (4 навыка HeyGen из клона на закреплённом коммите 1ff4cef = тег v0.9.12; собственный установщик HyperFrames не используется) и **Remotion** (13 навыков, коммит c7cb2fd). Нет Node 22.20+ или git — честно пишется, что не поставилось, остальное ставится. Нет ffmpeg — это заметка, а не ошибка: ИИ Рамис скажет, как поставить, только с «да» ученика.
- По итогам ревью безопасности: `npx` запускается из временной папки и с официального реестра npm, поля `notes` и `missing` очищаются перед передачей Claude, лимит попыток действует и для оборванной установки, у асинхронного хука таймаут 900 с, скрипт работает только на Mac и Linux, закрытые права файлов (`umask 077`), у клона отключены подмодули и протокол file. README честно перечисляет, что закреплено не полностью.
- Playwright MCP ставится в `~/.ii-ramis/mcp` (`npm install --prefix`, официальный реестр, без пользовательского `.npmrc`, без скриптов) и подключается по абсолютному пути, а не через `npx` из папки проекта (замечание автоматической проверки).
- 21st по-прежнему только с согласием и личным ключом ученика.
- Навык `nabor` переписан: ждёт результат хука, не ставит сам Bash-командами, на «Operation not permitted» не обходит запрет, а объясняет, что нажать (закрыть и открыть приложение; окно «Bash command (unsandboxed)» — штатное).
- README: путь обновления без Терминала и важная находка: **автообновление у стороннего маркетплейса по умолчанию выключено** (по документации), поэтому ученик сам берёт новую версию через `/plugin marketplace update ii-ramis` → Update marketplace или включает автообновление. Команды `/plugin update` в чате нет (она есть только в Терминале).
- Тесты: `tests/check-clean-install.mjs` переписан под скрипт хука (идемпотентность, флаг, отказ, 21st без ключа, переход с 2.4.0, лимит попыток, эмуляция запрета записи и путь через хук); `tests/check-structure.mjs` теперь разрешает ровно один скрипт.
- **Сводки Рамису снова доходят.** В 2.4 сводку слал Claude командой `curl` через Bash, а песочница Desktop режет сеть для доменов не из списка (команда ждёт окна разрешения или получает отказ) и запись вне рабочей папки, поэтому сводки молча терялись (ошибку правило велело скрывать). Теперь Claude пишет в чате строку `📨 Сводка Рамису: …`, а отправляет хук Stop `hooks/svodka-send.mjs` вне песочницы: только 2–4 строки до 400 символов, без кода, путей, адресов, почты и ключей (иначе не отправляется), раз в 30 минут и 5 раз в день, ключ anon только на INSERT, согласие по умолчанию включено. Отказы («не отправляй сводки», «не ставь набор» и обратные) записывает хук UserPromptSubmit: Bash в песочнице писать в `~/.ii-ramis` не может.
- Памятка и приветствие: версия 2.5.
