# Урок 4: первый сайт — визитка → интернет → форма заявок

Цель ученика: у него есть своя страничка по ссылке, на ней форма «Оставить заявку», и заявки попадают в таблицу, которую видит только он.
Путь: у себя на компьютере (localhost) → в интернете (Vercel) → форма пишет в базу (Supabase).
Стек для новичка: обычные файлы `index.html`, `style.css`, `script.js` без фреймворков. Усложнять (Next.js) — только если ученик сам попросит.

Правило урока: после КАЖДОГО шага — проверка. Не идём дальше, пока проверка не прошла. Результат шага сообщай в 3 строки (что сделал, что значит, что посмотреть).

Одна новая идея за раз. Порядок идей: папка и сохранения → страница → localhost → ссылка в интернете → ключи → форма.

## Шаг 3. База заявок (Supabase)

Что нужно от ученика (🙋): войти в Supabase в браузере и создать проект (Free), задать пароль базы и записать его себе (мне не присылать). Дальше сам.
Скажи ученику: «Supabase — это тетрадь заказов. Сейчас заведём в ней страницу «заявки»».

SQL, который нужно один раз выполнить в SQL Editor (даю ученику готовый текст, он вставляет и жмёт Run; если подключён Supabase MCP — выполняю сам):

```sql
create table public.leads (
  id uuid primary key default gen_random_uuid(),
  created_at timestamptz not null default now(),
  name text not null check (char_length(name) between 1 and 100),
  contact text not null check (char_length(contact) between 3 and 200),
  message text check (char_length(message) <= 1000)
);
alter table public.leads enable row level security;
create policy "anyone can send a lead" on public.leads
  for insert to anon with check (true);
```

Что это значит человеческим языком: таблица заявок есть, охранник (RLS) включён, гость может только ПОЛОЖИТЬ заявку и не может её прочитать или удалить. Читает только владелец в панели.

Проверка шага: ученик видит в Table Editor таблицу `leads` (🙋 один вопрос).

## Шаг 4. Ключи под замком

Объясни: «У Supabase два ключа. Публичный (anon) можно показывать на сайте, у него права гостя. Секретный (service_role) никогда не кладём на сайт».
- Из Project Settings → API нужны ТОЛЬКО адрес проекта (Project URL) и публичный ключ (anon / publishable). service_role не просим и не используем.
- Эти два значения кладу в `config.js` (они публичные по смыслу и защищены правилами из шага 3). Ученик вставляет их сам, я их не угадываю.
- Если ученик случайно прислал секретный ключ (service_role, длинный токен, пароль базы): не повторяй его, скажи убрать сообщение, и сменить ключ в панели.
- `.env` в `.gitignore` уже есть с шага 0. Если ключи нужны для чего-то ещё — запусти форму ключей (`node "${CLAUDE_PLUGIN_ROOT}/scripts/key-form.mjs" --project "<папка>" --vars ИМЯ`), ученик вставит значение в браузере; значения никогда не читать назад.

Проверка шага (сам): `git check-ignore .env` (если файл есть) и поиск в коде строки `service_role` — должно быть пусто. Содержимое `.env` не читать.

## Шаг 5. Форма пишет в базу

Делаю сам: форма в `index.html` (имя, контакт, сообщение, невидимое поле-ловушка для ботов), `script.js`: POST на `<Project URL>/rest/v1/leads` с заголовками `apikey`, `Authorization: Bearer <anon>`, `Content-Type: application/json`, **`Prefer: return=minimal`** (без него вставка попытается вернуть строку, а читать гостю нельзя). Защита: ловушка для ботов, обрезка длины, сообщение пользователю при ошибке, таймаут запроса 8 секунд.
Сохранение: коммит `feat: форма заявок в Supabase`, публикация обновления на Vercel.

Проверка шага (сам, обязательно перед «готово»):
1. Playwright открывает ссылку Vercel (не localhost).
2. Заполняет форму тестовыми данными (имя «Тест ИИ Рамис») и нажимает отправить.
3. Смотрит сетевые запросы: POST на `/rest/v1/leads` вернул статус 201.
4. Видит на странице сообщение «Спасибо, заявка отправлена».
5. 🙋 Просит ученика открыть Table Editor → leads и подтвердить: «строка «Тест ИИ Рамис» есть?» После подтверждения предлагает удалить тестовую строку (удаление только с его «да»).

## Если застряли

- Страница пустая на Vercel: смотрю статус деплоя и логи (`npx vercel logs` / панель), открываю консоль браузера через Playwright.
- Ответ 401 / 403 от Supabase: чаще всего неверный ключ или нет политики insert для anon. Проверяю текст ошибки, не меняю права «на всё разрешить».
- Ответ 400: название колонок в форме не совпадает с таблицей.
- Ответ 42501: забыл `Prefer: return=minimal`.
- Два раза подряд не вышло на одном месте: честно сказать ученику, не гадать в третий раз, записать «застряли» (хук запишет сам) и предложить показать проблему Рамису.
