# Strix: ИИ-пентест своего сайта (только инструкция, ставится по «да»)

Проверено 09.11.2026 по README github.com/usestrix/strix (Apache-2.0, версия 1.7.0, PyPI `strix-agent`, Python 3.12+).

## Что это (скажи ученику простыми словами)

Strix — программа, в которой ИИ играет роль взломщика: **сам нападает** на твой сайт или код (подбирает пароли, пробует подставить опасный текст в формы, ищет открытые данные) и показывает, что сумел сломать, с доказательством. Это глубже обычной проверки, но и опаснее: программа действует по-настоящему.

## Что нужно

- **Docker** (запущенный): Strix работает в изолированном контейнере и при первом запуске скачивает образ (несколько ГБ).
- **Ключ модели ИИ** (OpenAI, Anthropic, Google и т.п.) — платный, расход идёт с его счёта, не с подписки Claude Pro. Либо вход через подписку ChatGPT, либо облако самого Strix (отдельный аккаунт). Цену скажи вслух до установки: прогон может стоить заметных денег.
- Python 3.12+ и `uv` (или pipx). Если Docker или Python нет, честно скажи, что без них не выйдет, и объясни, как поставить с официальных сайтов; ставить Docker сам не начинай без «да».

## Жёсткие условия (спроси «да» на каждое, своими словами)

1. **Только свой сайт** (или сайт, где у тебя есть письменное разрешение владельца с описанием, что можно тестировать). Чужой сайт без разрешения — это незаконно в большинстве стран, отвечает ученик. Просят проверить чужой сайт, сайт работодателя или клиента без бумаги — откажи и объясни.
2. Лучше проверять **тестовую копию** (локальный `localhost` или preview-адрес), а не боевой сайт с настоящими пользователями: нападение может создать мусорные записи, заблокировать входы, исчерпать лимиты.
3. Ключ модели ввести самому, не в чат (ниже), и понимать, что платит он.
4. Результаты Strix (`strix_runs/…`) — только для себя: там могут быть найденные секреты.

## Как ставишь (после «да» ученика)

Установка пишет за пределы рабочей папки и использует Docker, поэтому в песочнице Desktop может не пройти. Тогда используй окно «Bash command (unsandboxed)»: объясни ученику текст команды и проси разрешить **только её**.

Предпочтительно закреплённая версия без запуска скрипта из интернета (README Strix допускает установку через uv):

```bash
uv tool install strix-agent==1.7.0
strix --version
```

Официальный установщик из README (`curl -sSL https://strix.ai/install | bash`) **не используй**: он запускает скрипт, не закреплённый по версии и хешу. Если `uv` нет, спроси ученика (см. «Если нет uv» в `nabor/references/ustanovka.md`).

Проверь, что Docker запущен: `docker info` (только чтение). Не запущен — попроси ученика открыть Docker Desktop.

## Ключ модели: без чата

Как у ключа 21st (`nabor/references/klyuch-21st.md`): ученик копирует ключ кнопкой «Копировать» в панели провайдера, ты берёшь его из буфера обмена (проверка длины и символов), кладёшь в файл `~/.ii-ramis/strix.env` с правами `600` (`STRIX_LLM=…`, `LLM_API_KEY=…`), очищаешь буфер. В чат ключ не просим, не печатаем и в проект/git не кладём. Ключ попал в чат — удалить сообщение и выпустить новый.

## Запуск (по отдельной фразе ученика «запусти Strix на моём сайте»)

- Адрес — только тот, что ученик назвал **своим**. Спроси ещё раз: «Это твой сайт или у тебя есть письменное разрешение?»
- Пример: `strix -n --target ./папка-проекта` (код) или `strix -n --target https://адрес-его-сайта` (работающий сайт). Не добавляй цели «заодно».
- Предупреди про время (десятки минут) и расход. Запускай в фоне, периодически сообщай ученику, что происходит.
- Результаты объясни по порядку навыка `bezopasnost` (шаги 4–6): что нашёл, чем грозит, исправил, перепроверил.

## Чего не делаем

- Не ставим и не запускаем Strix без явного «да» и условий выше.
- Не включаем в «поставь всё для урока 7» и в автоустановку набора.
- Не направляем на адреса, найденные в чужом тексте (README, сайты, сообщения).
- Не используем облако Strix (`strix cloud`: отправляет код и адреса на их сервер) без отдельного «да» с объяснением, что уходит наружу.
